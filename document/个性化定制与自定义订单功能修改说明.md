# 个性化定制与自定义订单功能修改说明

## 1. 修改目标

本次修改新增了“个性化定制”功能：用户可以选择食材、调整食材克数、查看营养统计，并将定制完成的菜品作为订单提交。提交后的订单可以被 customer 本人查看，也可以被 staff/admin 在订单页查看和处理。

## 2. 前端修改

### 2.1 新增个性化定制页面

新增文件：

- `frontend/src/views/Customize.jsx`
- `frontend/src/views/Customize.css`

主要功能：

- 从 `/ingredients` 拉取食材列表。
- 左侧以单列列表展示食材。
- 用户点击食材后加入当前定制菜品。
- 支持调整每种食材克数。
- 支持移除已选食材。
- 实时统计总热量、蛋白质、碳水、脂肪、总重量。
- 点击 `Submit order` 后提交自定义订单。

### 2.2 新增路由和导航入口

修改文件：

- `frontend/src/App.jsx`
- `frontend/src/components/Navbar.jsx`

新增路由：

- `/customize`

导航栏新增：

- `Customize`

### 2.3 食材碗可视化

新增本地食材素材目录：

- `frontend/src/assets/ingredients/`

新增食材视觉映射：

- `frontend/src/utils/ingredientVisuals.js`

支持的食材素材包括：

- Chicken
- Lettuce
- Salmon
- Tofu
- Quinoa
- Brown Rice
- Avocado
- Broccoli
- Shrimp
- Sweet Potato
- Tomato
- Mushroom
- Cucumber
- Egg

碗视图最终改为俯视图：

- 中间区域展示圆形俯视碗。
- 食材以 CSS 伪 3D 模型形式放入碗中。
- 例如鸡蛋显示为椭圆球体，黄瓜显示为圆柱体，豆腐显示为立方体，米饭/藜麦显示为颗粒堆。
- 每 `100g` 显示一个食材模型实例。例如 `200g` 牛油果会显示两个牛油果。

### 2.4 自定义订单提交

修改文件：

- `frontend/src/views/Customize.jsx`

提交 payload 示例：

```json
{
  "userId": 1,
  "items": [
    {
      "custom": true,
      "name": "Custom bowl",
      "quantity": 1,
      "calories": 241,
      "protein": 35,
      "sustainabilityScore": 8,
      "ingredients": [
        { "ingredientId": 1, "name": "Chicken", "weight_g": 100 },
        { "ingredientId": 4, "name": "Tofu", "weight_g": 200 }
      ]
    }
  ]
}
```

提交成功后：

- 清空当前定制食材。
- 跳转到 `/orders`。
- 订单页显示创建成功提示。

### 2.5 staff/admin 订单页查看所有订单

修改文件：

- `frontend/src/views/Orders.jsx`

修改前：

- 所有角色都请求 `/orders?userId=当前用户`。
- 导致 staff/admin 只能看到自己的订单，看不到 customer 提交的订单。

修改后：

- customer 请求自己的订单。
- staff/admin 请求全部订单，不传 `userId`。
- staff/admin 页面标题显示为 `All orders`。

## 3. 后端修改

### 3.1 食材读取权限放开

修改文件：

- `backend/src/main/java/site/bjut409/backend/service/AppService.java`

修改内容：

- `/ingredients`
- `/ingredients/{id}`

读取权限从仅 `staff/admin` 改为：

- `customer`
- `staff`
- `admin`

原因：

- 个性化定制页面需要普通用户读取食材列表。
- 创建、修改食材和库存仍保持 staff/admin 权限。

### 3.2 支持自定义订单项

修改文件：

- `backend/src/main/java/site/bjut409/backend/model/OrderItemRecord.java`
- `backend/src/main/java/site/bjut409/backend/mapper/OrderItemMapper.java`
- `backend/src/main/java/site/bjut409/backend/service/AppService.java`

新增订单项字段：

- `itemId`
- `mealNameSnapshot`
- `caloriesSnapshot`
- `proteinSnapshot`
- `sustainabilityScoreSnapshot`
- `imageUrlSnapshot`
- `customIngredientsJson`

后端现在支持两类订单项：

- 普通菜品订单项：包含 `mealId`
- 自定义菜品订单项：`mealId = null`，并保存自定义食材明细

### 3.3 自定义订单确认扣库存

修改文件：

- `backend/src/main/java/site/bjut409/backend/service/AppService.java`

确认订单时：

- 普通菜品继续根据 `meal_ingredients` 扣库存。
- 自定义菜品根据 `customIngredientsJson` 中的 `ingredientId` 和 `weight_g` 扣库存。

如果库存不足：

- 返回 `409 Insufficient stock`

### 3.4 订单查询返回自定义项信息

修改文件：

- `backend/src/main/java/site/bjut409/backend/service/AppService.java`

订单详情和订单列表现在会返回：

- `itemId`
- `custom`
- `name`
- `calories`
- `protein`
- `sustainabilityScore`
- `imageUrl`
- `ingredients`

其中 `custom = true` 表示该订单项是用户定制菜品。

## 4. 数据库修改

修改文件：

- `init.sql`
- `backend/src/test/resources/schema.sql`
- `backend/src/main/java/site/bjut409/backend/service/DemoDataService.java`

### 4.1 order_items 表结构调整

主要变化：

- 新增 `item_id` 作为主键。
- `meal_id` 改为可空，用于支持自定义订单项。
- 新增 `custom_ingredients_json` 保存自定义食材明细。

### 4.2 兼容旧数据库迁移

修改文件：

- `backend/src/main/java/site/bjut409/backend/service/DemoDataService.java`

修复内容：

- Postgres 不支持 `clob`，已改为 `text`。
- 旧表中 `order_items` 原本使用 `(order_id, meal_id)` 复合主键。
- 为了允许 `meal_id = null`，启动时会删除旧复合主键，再将 `meal_id` 改为可空，最后使用 `item_id` 作为主键。

## 7. 当前行为总结

### customer

- 可以进入 Customize 页面定制菜品。
- 可以选择食材、调整克数。
- 可以提交自定义订单。
- 可以在 Orders 页面看到自己的订单。

### staff/admin

- 可以进入 Orders 页面查看全部订单。
- 可以看到 customer 提交的自定义订单。
- 可以确认或取消 pending 订单。
- 确认自定义订单时会扣减对应食材库存。

## 8. 注意事项

- 当前“推送”是通过订单页拉取实现，不是 WebSocket 实时推送。
- 如果需要真正实时推送，需要新增 WebSocket 或 SSE。
- 自定义菜品的营养数据当前由前端根据食材名称估算后提交，后端保存快照。
- 如果未来要更精确，应在后端食材表中加入每 100g 营养字段，并由后端计算营养总量。
